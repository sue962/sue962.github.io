의료 영상 질의응답 연합학습 파이프라인 Medical VQA Federated Learning Pipeline

환자 데이터를 병원 밖으로 내보내지 않고 의료 영상 질의응답 모델을 학습시킬 때, 답변 품질이 어떻게 달라지는지 비교했습니다. 숫자가 올라간 조건에서 그 이유를 네 갈래로 분해해 확인했습니다. Comparing how answer quality changes when a medical visual question answering model is trained without patient data leaving the hospital. The centre of this project was taking the one condition where the score went up and breaking down where that gain actually came from.

담당 범위Scope

연합학습 파이프라인 개발과 실험 이력 관리, 결과 검증을 맡았습니다. 저장소 커밋 41건 가운데 28건이 제 작업입니다.

I worked on the federated pipeline, experiment provenance and result verification — 28 of the repository's 41 commits are mine.

이 프로젝트에서 가장 많이 한 일은 점수가 맞는지 확인하는 일이었습니다. 연합학습은 서버가 클라이언트의 가중치를 덮어쓰거나 다른 클라이언트의 상태를 복원하면, 틀린 방법에 그럴듯한 점수가 붙습니다. 실행이 성공했다는 메시지만으로는 그걸 알 수 없습니다. Most of my time here went into checking that a score belonged to the method it was filed under. In federated training a server update can overwrite a local head or restore another client's state, producing a plausible score for the wrong method — and a “run succeeded” message will not tell you that.

데이터 분할 기준Splitting images, not questions

  • 한 이미지에 여러 질문이 달려 있습니다. 질문 단위로 학습·검증·평가를 나누면 같은 X-ray가 세 묶음에 동시에 들어갑니다. 모델이 평가 때 처음 보는 영상이어야 하는데 이미 학습에서 본 것이 됩니다. 그래서 질문이 아니라 이미지 단위로 나눴습니다.
  • Each image carries several questions. Splitting by question puts the same X-ray into training, validation and test at once, so an image the model is meant to be seeing for the first time has already been trained on. The split is therefore by image, not by question.
  • 원본 데이터를 먼저 점검했습니다. 질문·답변 쌍 2,248건 가운데 완전히 같은 중복 4건을 찾아 제거했고, 어떤 질문도 참조하지 않는 이미지 1장을 제외했습니다. 남은 2,244건과 314장으로 분할을 구성했습니다.
  • The source was audited first. Four exact duplicate question–answer instances were found among 2,248 pairs and removed, along with one image no question referenced — leaving 2,244 pairs across 314 images to partition.
  • 분할이 지켜지는지 검사로 확인했습니다. 질문 ID가 모두 고유한지, 세 묶음 사이에 이미지가 겹치지 않는지, 학습 이미지 하나가 정확히 한 클라이언트에만 배정됐는지를 확인했습니다.
  • Checks confirmed the split holds: question IDs unique, no image shared between the three sets, and exactly one client assignment per training image.
  • 평가용 데이터는 쓰지 않았습니다. 비교는 검증 데이터로만 했고, 평가 데이터는 최종 평가 규칙이 정해질 때까지 예측도 채점도 하지 않은 채로 두었습니다.
  • Test data stayed untouched. All comparisons ran on validation; test was neither predicted nor scored, pending an agreed final evaluation protocol.

비교 설계Comparison design

모델은 닫힌 질문(예/아니오 같은 고정 답변)과 열린 질문을 각각 다른 출력부로 처리합니다. 연합학습에서 이 출력부를 어디까지 공유하느냐에 따라 결과가 달라지는지를 보려고, 공유 범위만 다른 조건을 나란히 두었습니다.

The model answers closed questions (fixed answers such as yes/no) and open questions through separate heads. To see whether how much of that is shared changes the outcome, the conditions differ only in sharing policy.

조건Method 공유 범위What is shared
A연합학습 없이 한곳에서 전부 학습 (기준선)Centralised training on all data (baseline)
B인코더와 두 출력부를 모두 공유Encoder and both heads shared
C열린 질문 출력부만 각 기관에 남김Open head kept local to each client
L두 출력부를 모두 각 기관에 남김Both heads kept local
R닫힌 질문 출력부만 각 기관에 남김Closed head kept local
  • L과 R은 비교를 위해 추가한 조건입니다. C가 B보다 나아 보일 때, 그게 "열린 질문 출력부를 남긴 것" 때문인지 아니면 "뭐라도 남기면 나아지는 것"인지 구분할 수 없습니다. 둘 다 남긴 조건(L)과 반대쪽만 남긴 조건(R)을 같이 돌려야 답이 나옵니다.
  • L and R exist to make C interpretable. If C beats B, that alone cannot tell you whether keeping the open head local mattered or whether keeping anything local would do. Running both-local (L) and the opposite-only case (R) is what separates them.
  • 조건 사이에 다른 변수가 끼지 않게 맞췄습니다. 같은 시드에서는 모든 방법이 같은 초기 가중치에서 출발하고, 같은 데이터 로더와 학습 루프, 같은 채점기를 씁니다. 기준선 A의 3에포크는 연합학습 3라운드와 질문 노출 횟수를 맞춰서 정했습니다.
  • Nothing else was allowed to vary. Within a seed every method starts from the same initial checkpoint and uses the same loader, training loop and scorer. The baseline's three epochs match the three question exposures of three-round federated training.
  • 맞추지 못한 차이는 적어 두었습니다. 연합학습은 라운드마다 옵티마이저가 초기화되지만 기준선 A는 에포크 사이에 상태를 유지합니다. 질문 노출 횟수를 맞췄다고 해서 이 차이가 없어진 것은 아니라서, 해결됐다고 쓰지 않고 남아 있는 차이로 적었습니다.
  • What could not be matched was written down. Federated optimisers reset each round while the centralised baseline carries state across epochs. Matching question exposure does not erase that, so it is recorded as a remaining difference rather than a resolved one.
  • 선택적 공유가 통신량을 줄여 주지는 않습니다. 일부만 집계에 쓰더라도 전송은 여전히 모든 파라미터를 싣고 갑니다. 이 점을 성과로 적지 않았습니다.
  • Selective aggregation is not a communication saving. Transport still carries every parameter group even when only some are aggregated, so it was not claimed as a benefit.

결과Results

시드 3개를 반복한 평균입니다. C가 B보다 나은지는 데이터가 어떻게 나뉘어 있느냐에 따라 부호가 바뀌었습니다. 기관마다 영상 부위가 치우친 non-IID 조건에서는 오히려 C가 낮았습니다.

한곳에서 학습한 A가 세 지표 모두에서 가장 높았습니다. 연합학습이 더 낫다는 결과가 아니라, 공유 범위를 바꾸면 결과가 조건에 따라 달라진다는 것이 이 비교가 보여주는 내용입니다. IID에서 C가 L을 앞선 폭은 0.26%p였고 시드별 방향도 엇갈렸습니다.

Centralised A scored highest on all three metrics. The finding is not that federated training wins, but that changing the sharing policy produces condition-dependent results. Under IID, C led L by 0.26 points with seeds pointing in different directions.

점수 차이 분해Breaking down the gain

IID에서 C가 B보다 F1이 2.22%p 높았습니다. 여기서 멈추면 "열린 질문 출력부를 각 기관에 남기면 좋다"로 읽힙니다. 그런데 채점 방식을 보면 검증 질문 102개 중 73개는 정답이 모델이 고를 수 있는 답변 목록 밖에 있습니다. 이 질문들은 정확히 맞출 수가 없고, 단어가 일부 겹치는 만큼만 점수를 받습니다.

Under IID, C scored 2.22 points higher than B. Stopping there reads as “keeping the open head local helps.” But 73 of the 102 validation questions have a gold answer outside the list the model can choose from — they cannot be answered exactly, and earn credit only for partial word overlap.

그래서 차이를 네 칸으로 나눠 봤습니다. 정답이 목록 안인지 밖인지, 그리고 정확히 맞췄는지 단어만 겹쳤는지입니다.

So the difference was split four ways: whether the gold answer was inside or outside the list, and whether the match was exact or partial overlap.

IID에서 늘어난 2.22%p 가운데 2.01%p, 약 90%가 "목록 밖 · 부분 일치"에서 나왔습니다. 정답을 맞춰서 올라간 점수가 아니라, 맞출 수 없는 질문에서 단어가 더 겹쳐서 올라간 점수입니다. 네 칸의 합은 반올림 전 기준으로 합계와 일치합니다. Of the 2.22-point IID gain, 2.01 points — about 90% — sit in “outside list · partial”: not answers the model got right, but more word overlap on questions it could not get right. The four cells sum to the total before rounding.

그래서 이 숫자를 성과로 쓰지 않았습니다. 분모에서 목록 밖 질문을 빼면 점수가 올라가 보이지만, 그건 모델이 못 맞추는 질문을 평가에서 빼는 셈입니다. 102문항을 모두 채점에 남긴 채 차이를 분해해서 어디서 온 점수인지 보고했습니다. 단어가 겹친다고 의학적으로 맞는 답이라는 뜻은 아닙니다. That is why the number was not reported as a win. Dropping the out-of-list questions from the denominator would raise the score, but it would do so by deleting the questions the model cannot answer. All 102 questions stayed in scoring and the difference was decomposed instead. Word overlap is not evidence of clinical correctness.

  • 학습을 더 돌려도 해결되지 않는 문제입니다. 목록에 없는 답은 학습 시간을 늘린다고 생기지 않습니다. 별도로 생성 방식 시험을 64개 예시로 돌려 봤지만, 목록 밖 73개 질문에서 정확히 맞춘 경우는 없었습니다. 이 결과도 본 실험에 섞지 않고 따로 적었습니다.
  • More training does not fix this. An answer absent from the list cannot be produced by training longer. A separate 64-example generative pilot was run, and it produced no exact matches on those 73 questions — a result kept separate from the main experiments rather than folded into them.

재현성Reproducibility

  • 저장한 모델을 전부 다시 채점했습니다. 51번의 실행에서 모델 99개가 나왔고, 모델마다 검증 질문 216개 예측을 다시 돌려 점수가 같은지 확인했습니다. 비교 항목 180건을 짝지어 대조하고 모델 9개는 직접 다시 실행했습니다.
  • Every export was rescored. The 99 models produced by 51 runs were saved, and each was replayed over all 216 validation questions to confirm the scores still matched. 180 paired comparison entries were reconciled and nine models were re-run directly.
  • 파일 이름은 증거로 치지 않았습니다. 예전 실행 하나는 파일명이 맞는데도 예측 해시가 일치하지 않았고, 일부 초기 가중치는 남아 있지 않았습니다. 이후로는 설정·가중치·예측·점수를 서로 연결해 기록하고, 기존 기록을 덮어쓰지 않게 했습니다. 되찾지 못한 파일은 복원하지 않고 "확인 불가"로 남겼습니다.
  • Filenames were not accepted as evidence. One earlier run had the right filename but a prediction hash that did not match, and some initial checkpoints no longer existed. Records now link settings, weights, predictions and scores without overwriting earlier ones, and files that could not be recovered are left marked unavailable rather than reconstructed.
  • 서버가 보낸 값을 직접 꺼내 확인했습니다. 집계가 제대로 됐는지, 각 클라이언트가 받은 가중치가 맞는지를 텐서 단위로 비교했습니다. 라운드가 넘어갈 때 각 기관의 출력부가 그대로 이어지는지도 "복원됨" 표시를 믿지 않고 값으로 확인했습니다. 이 검사에 실패한 실행은 비교 표에서 제외했습니다.
  • Values the server sent were checked tensor by tensor — whether aggregation was computed correctly and whether each client received the weights it should have. Continuity of each client's local head across rounds was verified from the values rather than from a “restored” flag, and runs that failed these checks were excluded from the comparison table.
  • 같은 예측인데 파이썬 버전에 따라 점수가 달랐습니다. 3.9에서 다시 채점해 보니 소수점 아래가 미세하게 어긋났습니다. 그래서 재채점은 3.12로 버전을 고정했습니다.
  • A floating-point mismatch surfaced across Python versions. Rescoring under 3.9 produced slightly different values, so strict rescoring is pinned to 3.12.
  • 확인하지 못한 범위는 적어 두었습니다. 지금까지의 검사는 모두 같은 컴퓨터에서 한 것이라, 다른 환경에서의 독립 재현을 증명하지는 않습니다.
  • The unverified scope is stated. All of these checks ran on the same machine, so they do not establish independent reproduction elsewhere.
