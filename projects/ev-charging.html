담당 범위Scope

제가 맡은 범위는 데이터 수집, 정제, 공간 결합, 데이터베이스 설계입니다. 외부 출처를 이용한 속성 증강은 제 담당이 아니었고, 이 페이지에 적은 건 전부 제가 직접 한 일입니다. My scope was retrieval, cleaning, spatial integration and database design. Attribute augmentation from external sources sat outside my part; everything on this page is work I did myself.

결과물은 NSW 전역 충전소 1,939건이 SA4 통계 지역에 배정된 상태로 들어 있는 DuckDB 데이터베이스입니다. 스키마는 DDL로 다시 만들 수 있고, 공간 질의는 Spatial 확장을 사용합니다.

The output is a DuckDB database holding 1,939 NSW charging-station records, each assigned to an SA4 statistical area. The schema can be rebuilt from DDL, and spatial queries run on the Spatial extension.

원본 데이터 상태What the source actually contained

  • 종류 컬럼에 상태가 섞여 있었습니다. Charger_Type에 AC 1,427행과 DC 433행 외에, 충전기 종류가 아니라 운영 상태를 뜻하는 Upcoming 98행이 함께 들어 있었습니다. 종류와 상태를 별도 컬럼으로 분리하고, Upcoming 행에 한해 출력값으로 종류를 추정했습니다(43kW 초과는 DC). 원본 라벨은 지우지 않고 남겼습니다.
  • Status was mixed into the type column. Charger_Type held 1,427 AC and 433 DC rows, plus 98 "Upcoming" rows that described status rather than charger type. I split type and status into separate columns and inferred type from the power rating for those 98 rows only (above 43 kW as DC), keeping the original labels intact.
  • 출력값이 자유 문자열이었습니다. Charger_rating에 2x350kW처럼 여러 출력이 한 문자열로 들어가거나, 숫자 대신 "AC"라는 글자가 들어 있었습니다. 최고 출력만 수치로 추출하되 원본 문자열을 함께 보관해, 1,425행에서 사용 가능한 출력값을 확보했습니다.
  • Power ratings were free text. Charger_rating sometimes packed several outputs into one string such as 2x350kW, or carried the word "AC" instead of a figure. I extracted the highest output as a number while retaining the original string, leaving 1,425 rows with a usable power value.
  • 우편번호가 세 가지로 망가져 있었습니다. 121행 공백, 10행은 주(state)명이 붙음, 25행은 주소와 불일치. 공백 중 120행은 주소에서 복구하고 주 접두어는 제거했지만, 불일치 25행은 고치지 않고 location_conflict로 표시했습니다. 어느 쪽이 맞는지 판단할 근거가 없었기 때문입니다.
  • Postcodes were broken three different ways. 121 blank, 10 with a state name attached, 25 disagreeing with the address. I recovered 120 of the blanks from the address and stripped the state prefixes, but left the 25 conflicts uncorrected and flagged as location_conflict — there was no basis for deciding which side was right.
  • 빈 값은 채우지 않았습니다. 역 이름이 1,438행 비어 있었지만 추정해서 채우지 않았고, 주소 733건에 들어 있던 줄바꿈만 제거했습니다.
  • Blanks were left blank. Station names were missing on 1,438 rows and were not imputed; I only removed the line breaks found inside 733 addresses.

The row count fell because duplicates were merged, not because data was discarded; the postcode count rose because values were recovered from the address, not invented. Each figure is traceable to the operation that produced it through the cleaning log.

정제 과정의 판단 기준Judgment calls

  • 중복은 근거가 있을 때만 합쳤습니다. 운영사명·충전기 종류·좌표(소수점 5자리)로 37행 17그룹을 후보로 잡고, 역 이름이 서로 모순되지 않을 때만 병합했습니다. 빈 이름은 모순으로 보지 않았고, 이름이 서로 다른 1그룹은 합치지 않고 남겼습니다. 결과적으로 16그룹을 병합해 19행을 제거했습니다. 병합 시 플러그 수는 가장 큰 값, 주소는 가장 긴 값을 남겼고, 출력값이 있는 경우 원본 문자열과 파생값을 같은 레코드에서 함께 가져왔습니다.
  • Duplicates were merged only with evidence. Normalised operator names, cleaned types and coordinates rounded to five decimals produced 37 candidate rows in 17 groups; a group was merged only when station names did not contradict each other. A blank name was not a contradiction, and the one group with two conflicting names was left unmerged — 16 groups merged, removing 19 rows. On merge I kept the largest plug count and the longest address, and where a numeric power existed, took the rating string and its derived values together from the same record.
  • 키를 직접 만들었습니다. 원본 식별자가 대부분 비어 있어 키로 쓸 수 없었습니다. 위치·운영사·종류·주소 순으로 정렬한 뒤, 같은 입력을 다시 정제하면 같은 ID가 나오도록 1,939행에 식별자를 부여했습니다. 실행할 때마다 ID가 바뀌면 이후 단계의 증거와 연결이 끊기기 때문입니다.
  • I generated the key. The original identifier was blank on most rows, so it could not serve as one. I sorted by location, operator, type and address, then assigned identifiers to all 1,939 rows so that cleaning the same input again reproduces the same IDs — if IDs shifted between runs, every downstream link to evidence would break.
  • 운영사 매핑 표를 분리해 두었습니다. 대소문자와 공백만 정리하면 50 → 49에 그쳤습니다. 같은 회사의 다른 표기(BP / BP Australia, Tesla / Tesla Motors)와 13자에서 잘린 이름까지 매핑해 41개로 통합했고, 이 표를 정제 코드와 분리해 보관해 이후 단계가 같은 이름을 쓰도록 했습니다.
  • The operator mapping lives on its own. Normalising case and spacing alone only took 50 names to 49. Mapping variant spellings of the same company (BP / BP Australia, Tesla / Tesla Motors) and names truncated at 13 characters brought it to 41, and I kept that table separate from the cleaning code so later stages resolve to the same names.

공간 결합Spatial integration

  • 원본에 좌표의 측지계가 적혀 있지 않아, ABS 경계와 같은 GDA2020(EPSG:7844)으로 가정하고, 확인한 것이 아니라 가정이라고 문서에 남겼습니다.
  • The source never states the datum of its coordinates, so I assumed GDA2020 (EPSG:7844) to match the ABS boundaries and recorded that as an assumption — keeping what was verified separate from what was assumed.
  • 경계에 걸친 점이 두 지역에 중복 배정되지 않도록 intersects 대신 within으로 먼저 배정하고, 포함되지 않은 점만 100m 이내 최근접 SA4를 찾아 nearest로 표시했습니다. 거리는 MGA zone 55(EPSG:7855)에서 계산했습니다.
  • To stop a point on a shared border from being assigned twice, I used within rather than intersects, then considered only unmatched points for a nearest SA4 within 100 m, flagged as nearest. Distances were computed in MGA zone 55 (EPSG:7855).
  • NSW 밖으로 잘못 배정되는 경우를 잡기 위해 전국 SA4 경계를 모두 사용했습니다. 결합 결과 행 수는 1,939로 변하지 않았고, 1,938행이 SA4 내부, 1행(EV1092)이 Sydney – Northern Beaches 경계 밖 약 1.8m로 최근접 배정됐습니다. 모든 배정 지역은 NSW 안에 있었습니다.
  • I used the full national SA4 boundaries to catch any assignment outside NSW. The join left the row count unchanged at 1,939: 1,938 points fell inside an SA4 region, and one (EV1092) sat about 1.8 m outside the Sydney – Northern Beaches polygon and was assigned to it as the nearest match. Every assigned region was in NSW.
  • 배정이 좌표 오차에 얼마나 민감한지 확인하려고 각 점에서 배정된 지역 경계까지의 거리를 재봤습니다. 최소 거리가 8.8m라, 2m 정도 위치가 흔들려도 배정은 바뀌지 않았습니다. 다만 이건 배정에 얼마나 여유가 있는지를 본 것이지 측지계나 좌표 오차 자체를 검증한 건 아닙니다.
  • To gauge how sensitive the assignment is to positional error, I measured each point's distance to its assigned boundary. The minimum was 8.8 m, so a shift of up to two metres would not move any point out of its polygon — and I noted that this does not verify the datum or bound the coordinate error itself.
  • 정제 단계에서 표시한 위치 불일치 25행은 여기서도 고치지 않았습니다. 이 행들의 SA4는 저장된 좌표가 들어 있는 지역입니다. 모든 행이 지역을 받았다는 뜻이고, 충전소의 실제 위치를 확인했다는 뜻은 아닙니다.

데이터베이스 설계Database design

  • 운영사와 지역을 별도 테이블로 분리해 같은 정보가 행마다 반복되지 않게 했습니다. 지역은 전국 SA4 108건을 모두 보관했고(폴리곤 89건, 지오메트리 NULL 19건), 운영사 별칭 13건은 별도 테이블에 두었습니다.
  • Operators and regions became their own tables so the same details are not repeated on every row. All 108 national SA4 records were kept (89 with polygon geometry, 19 with NULL), and the 13 operator aliases live in a separate table.
  • 우편번호와 SA4 코드는 숫자처럼 보이지만 VARCHAR로 저장해 앞자리 0과 비숫자 코드를 지켰고, 빈 값은 0이 아니라 NULL로 두었습니다.
  • Postcodes and SA4 codes look numeric but are stored as VARCHAR, preserving leading zeroes and official non-numeric codes; empty values are NULL, not zero.
  • 위경도 범위, 충전기 종류·상태의 허용값, 출력의 유한성과 양수 조건, 우편번호 4자리 형식을 CHECK 제약으로 스키마에 직접 넣었습니다. 적재 코드가 아니라 데이터베이스가 직접 지키게 했습니다.
  • Coordinate ranges, the allowed values for charger type and status, finite positive power figures and the four-digit postcode format are all CHECK constraints in the schema itself — enforced by the database, not by the loading code.
  • 좌표계를 타입 주석이 아니라 별도 컬럼으로 저장해 데이터베이스를 다시 열었을 때도 확인할 수 있게 하고, 두 geometry 컬럼에 R-tree 인덱스를 만들었습니다.
  • The CRS is held in its own column rather than a type note, so it can still be checked after the database is reopened, and both geometry columns carry R-tree indexes.
  • 적재 후 검증에서 공간 조인 결과(1,938 within, 1 nearest)가 데이터베이스 안에서도 그대로 재현되는지 다시 확인했습니다.
  • Post-load validation re-checks that the spatial assignment (1,938 within, one nearest) reproduces inside the database.

regions

공식 SA4 통계 지역을 코드 단위로 한 번씩 저장합니다. NSW 밖 오배정을 검증하기 위해 전국 108건을 모두 보관했고, 이 중 89건은 폴리곤, 19건은 지오메트리가 NULL입니다.

Stores each official SA4 statistical area once, by code. All 108 national records were retained so assignments outside NSW could be checked — 89 with polygon geometry, 19 with NULL.

PRIMARY KEY sa4_code · CHECK geometry_crs = 'EPSG:7844' · 108 rows

chargers

한 사이트 · 운영사 · 충전기 종류당 1행입니다. 플러그 하나가 아니라 한 운영사가 한 장소에서 제공하는 한 종류가 기준이며, 예정(upcoming) 행도 함께 보관합니다.

One row per site, operator and charger type — the grain is one type offered by one operator at one site, not an individual plug. Upcoming rows are kept.

허용값과 범위를 적재 코드가 아니라 스키마에서 지키도록 CHECK 제약으로 넣었습니다.

Allowed values and ranges are enforced by the schema through CHECK constraints rather than by the loading code.

CHECK charger_type ∈ (AC, DC, Unknown) · charger_status ∈ (existing, upcoming) · sa4_match ∈ (within, nearest) · postcode ~ [0-9]{4} · 1,939 rows

augmentation

증강 대상인 기존 DC 충전소 431건을 조회용으로 요약한 테이블입니다. 매칭 상태와 유효 증강 여부를 한 행으로 보여줍니다.

A query summary over the 431 existing DC charger records eligible for augmentation, giving match status and whether a valid augmentation exists in one row.

요약이 증거와 어긋나지 않도록, 매칭 여부와 상태값이 서로 모순될 수 없게 제약을 걸었습니다.

Constraints keep the summary from contradicting the evidence: the matched flag and the status value cannot disagree.

CHECK is_matched = (match_status = 'accepted') · 431 rows

augmentation_evidence

재현성Reproducibility

  • 파일마다 URL, 출처 엔드포인트, 수집 시각, 크기, SHA-256 체크섬을 기록했습니다. 다시 실행하면 로컬 파일의 크기·체크섬·파일명을 기록과 대조해, 일치하면 원래 수집 시각을 지킨 채 재사용하고 불일치하면 덮어쓰지 않고 멈춥니다. 다만 이 방식은 로컬 사본이 기록과 맞는지만 봅니다. 원격 파일이 그사이 바뀌었는지는 알 수 없습니다.
  • For every file I record the URL, source endpoint, retrieval time, size and a SHA-256 checksum. A later run compares the local file's size, checksum and filename against that record: on a match it reuses the file and preserves the original retrieval time; on a mismatch it stops rather than overwriting. As documented, this verifies the local copy against its recorded metadata — it does not detect changes to the remote file.
  • 수집은 data.gov.au CKAN API로 대상 CSV를 찾아 내려받고, ABS는 배포 페이지를 파싱해 셰이프파일 아카이브를 자동으로 받아 풀도록 했습니다. 로그인이나 API 키는 필요 없습니다.
  • Retrieval locates the target CSV through the data.gov.au CKAN API and parses the ABS download page to fetch and extract the shapefile archive automatically. Neither requires a login or an API key.
  • 수집·검증·적재 스크립트와 단위 테스트 6종으로 구성했고, macOS arm64 / Python 3.12 클린 환경에서 전체 흐름이 통과하는 것을 확인했습니다. 다른 운영체제까지는 확인하지 못했습니다.
  • The package comprises acquisition, validation and loading scripts with six unit-test modules, and the whole flow passes in a clean macOS arm64 / Python 3.12 environment — which, as the report states, does not establish compatibility across every operating system.
